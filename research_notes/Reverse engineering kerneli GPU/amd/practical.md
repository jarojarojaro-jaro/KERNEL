# AMD track: legal clarity + practical RE/optimization workflow for RX 7900 XTX (gfx1100)

Research date: 2026-10-17. Target: Radeon RX 7900 XTX 24 GB (gfx1100, RDNA3), Ubuntu Server (headless), ROCm 10.1.0, Mesa RADV. Workload: llama.cpp (Qwen3.8-27B GGUF). Everything below is dated/versioned; items marked **[unverified]** could not be confirmed from a primary source in this session.

## KQ-L1. Licenses of ROCm components relevant to kernels (what is open, what is binary-only)

### Takeaway
Virtually the entire AMD kernel-relevant stack is open source under permissive licenses (MIT / NCSA / Apache / GPLv3 for the debugger). As of ROCm 10.1.0 the only kernel-tooling pieces AMD still ships in binary form are the ROCprof Trace Decoder (.so, custom license) and AOCC CPU optimizations; AQLprofile is now MIT and open. Reverse engineering open-source libraries is simply "reading source" — no legal question arises.

### Cited Findings
- ROCm 10.1.0 license table (page header "AMD ROCm 10.1.0"): rocBLAS MIT, Tensile MIT, hipBLASLt MIT, MIOpen MIT, Composable Kernel MIT, HIP MIT, CLR ("AMD Compute Language Runtime") MIT, ROCR-Runtime "The University of Illinois/NCSA", llvm-project "Apache" (the page writes only "Apache"; the LLVM exception is not spelled out there), AQLprofile MIT, rocprofiler-sdk MIT, ROCgdb GPL v3.0 — [ROCm license page](https://rocm.docs.amd.com/en/latest/about/license.html)
- Same page, "Attention" note: "ROCprof Trace Decoder and AOCC CPU optimizations are provided in binary form, subject to the license agreement"; and "Proprietary products are only available on https://repo.radeon.com" — [ROCm license page](https://rocm.docs.amd.com/en/latest/about/license.html)
- rocprof-trace-decoder README: the headers are MIT-licensed, while the ".so and .dylib binaries use a custom" license; supported GPUs: Radeon 6000/7000/9000 series, Instinct MI200/MI300; "ROCm 7.13 and later include the decoder by default"; rocprofv3 looks for it in LD_LIBRARY_PATH or /opt/rocm/lib, else `--att-library-path`; repo is deprecated, source now in ROCm/rocm-systems — [rocprof-trace-decoder](https://github.com/ROCm/rocprof-trace-decoder)
- AQLprofile is now "an open source library that enables advanced GPU profiling and tracing on AMD platforms" (PMC + SQTT), MIT per Arch Linux packaging of hsa-amd-aqlprofile 7.2.x (upstream listed as github.com/ROCm/rocm-systems; older entries pointed at rocprofiler-register; Fedora points at github.com/ROCm/aqlprofile) — [AQLprofile docs](https://rocm.docs.amd.com/projects/aqlprofile/en/latest/what-is-aqlprofile.html); [Arch package](https://archlinux.org/packages/extra/x86_64/hsa-amd-aqlprofile/)
- AITER: MIT; "Fully supported" MI300X/MI325X (gfx942), "Supported" MI350/MI355X (gfx950), "Experimental" Radeon PRO W7900 (gfx1100), AI Max 300/400 (gfx1151), Radeon AI PRO R9700 (gfx1201); footnote: on RDNA "Triton and most FlyDSL kernels run", "Most CK and ASM kernels are CDNA-only" — [ROCm/aiter](https://github.com/ROCm/aiter)
- Mesa (RADV/ACO live in Mesa): "The core Mesa library is licensed according to the terms of the MIT license"; individual files carry SPDX tags — [Mesa license](https://docs.mesa3d.org/license.html)
- amdgpu kernel driver (drivers/gpu/drm/amd/amdgpu/amdgpu_drv.c) carries an MIT/X11-style header ("Permission is hereby granted, free of charge…"), i.e. dual-usable under GPL kernel + MIT — [amdgpu_drv.c](https://raw.githubusercontent.com/torvalds/linux/master/drivers/gpu/drm/amd/amdgpu/amdgpu_drv.c)
- umr (AMD's user-mode register/wave debugger) is MIT per AUR packaging; build deps: CMake, LLVM, libdrm, libpciaccess, ncurses; `cmake . && make -j install`; `UMR_NO_LLVM` disables shader disassembly; relies on kernel debugfs — [umr build docs](https://umr.readthedocs.io/en/main/build.html); [AUR umr](https://aur.archlinux.org/packages/umr)
- REA (morluto/rea) is MIT; it is a generic RE MCP/CLI (Ghidra/Hopper/IDA, JS/Electron, .NET). Its README/docs contain no AMD/ROCm/hsaco/code-object-specific support (grep for "amd|rocm|gfx|hsaco|code object" in README.md/docs returned only unrelated x86 "amd64" hits) — local clone at /tmp/claude-0/-home-user-KERNEL/2fec5121-746d-5a8c-9207-83ad66dddd8f/scratchpad/rea_clone/rea (read-only; [upstream](https://github.com/morluto/rea))

### Inferences
- For a hobbyist on gfx1100 the "reverse engineering" of AMD kernels is overwhelmingly *source-level*: rocBLAS/Tensile kernels (MIT), CK (MIT), llama.cpp HIP kernels (MIT), Mesa ACO (MIT). The compiler (LLVM AMDGPU) and the disassembler (`llvm-objdump` from /opt/rocm/llvm/bin) are open, so a binary → ISA round-trip is fully open-source.
- The only binary artifact you might be tempted to disassemble is rocprof-trace-decoder.so — but you don't need to: it is a plugin that decodes SQTT, and its output (stats_*.csv, ui_output JSON) is what you want. Treat it as "don't RE this one" to stay clean.
- REA adds nothing GPU-specific over `llvm-objdump`/RGA; it could at most drive Ghidra on the x86 host side of libggml-hip.so (e.g., to find where code objects are embedded), which `llvm-objdump --offloading` does directly.

### Gaps
- The license page lists llvm-project as plain "Apache"; whether ROCm's LLVM fork keeps the standard "Apache-2.0 WITH LLVM-exception" was not fetched from the repo LICENSE.TXT in this session (expected yes, **[unverified]**).
- The exact text of the rocprof-trace-decoder binary license (reverse-engineering clause) was not readable from the README.
- "rocm-llvm-alt" (closed-source AOCC-based optimizations) is not in the 10.1.0 table; its EULA wording **[unverified]**.

## KQ-L2. AMD proprietary EULAs (Radeon Software / AMDGPU-PRO) and the ISA document terms

### Takeaway
AMD's proprietary driver EULA forbids decompiling/disassembling "except as permitted by … applicable legislation" (EU law permits observation/testing and interoperability decompilation), but on a headless Ubuntu Server using ROCm + Mesa RADV you do not install any AMD-EULA-covered binary at all. The ISA PDFs are public but under a "Specification Agreement" that forbids *redistributing* the PDF, not using the knowledge.

### Cited Findings
- AMD Software EULA (copy archived in ChromiumOS portage overlay, "AMD Software End User License Agreement"), Section 2 Restrictions, lead-in: "except as permitted by this license or applicable legislation, you may not:" … "decompile, reverse engineer, disassemble or otherwise reduce the Software to a human-perceivable form;" — [ChromiumOS copy of AMD EULA](https://chromium.googlesource.com/chromiumos/overlays/portage/+/master/licenses/AMD)
- Current amd.com EULA page (https://www.amd.com/en/legal/eula/amd-software-eula.html) returned HTTP 503 twice in this session; the search index summary of it says it "bars decompiling, reverse engineering, disassembling, or otherwise reducing the Software to Source Code form, except as allowed by applicable law" — wording difference ("Source Code form" vs "human-perceivable form") between versions noted — [search summary; primary page unreachable](https://www.amd.com/en/legal/eula/amd-software-eula.html)
- Radeon Software for Linux (AMDGPU-PRO) download notes: downloading = accepting an EULA for the proprietary OpenGL/OpenCL/Vulkan (and AMF) drivers; "Open source software is also provided and is subject to the terms and conditions of the licenses included with such software" — [RPM Fusion thread quoting AMD](https://lists.rpmfusion.org/pipermail/rpmfusion-developers/2016-November/020849.html)
- ROCm 10.1.0 install docs: Instinct/Radeon use `amdgpu-install --usecase=rocm,graphics`; the graphics usecase pulls AMD's driver stack from repo.radeon.com (which the license page says is where "proprietary products" live) — [ROCm install](https://rocm.docs.amd.com/en/latest/install/rocm.html); [ROCm license page](https://rocm.docs.amd.com/en/latest/about/license.html)
- RDNA3 ISA Reference Guide, cover "15-August-2023", 600 numbered pages (PDF 609), front-matter "Specification Agreement": "1. You may review the Specification only (a) as a reference to assist You in planning and designing Your product, service or technology ('Product') to interface with an AMD product … and (b) to provide Feedback"; "2. … You may not (i) duplicate any part of the Specification; (ii) remove this Agreement or any notices from the Specification, or (iii) give any part of the Specification … to anyone else." Disclaimer: "No license, including implied or arising by estoppel, to any intellectual property rights is granted by this document." — [RDNA3 ISA PDF](https://gpuopen.com/download/rdna3-shader-instruction-set-architecture-feb-2023.pdf)
- GPUOpen ISA documentation hub lists RDNA4, RDNA3.5, RDNA3, RDNA2, RDNA1, CDNA1–5 PDFs as "publicly available PDFs"; also mentions machine-readable ISA specs — [GPUOpen AMD ISA documentation](https://gpuopen.com/amd-isa-documentation/)
- ROCm docs: Radeon RX 7900 XTX (gfx1100) is in the supported hardware table of ROCm 10.1.0 (released 2026-10-05) — [ROCm 10.1.0 release notes](https://rocm.docs.amd.com/en/latest/about/release-notes.html)

### Inferences
- **Clearly allowed for a hobbyist on this setup**: (1) reading/modifying every open-source kernel (rocBLAS, CK, llama.cpp, ACO); (2) compiling with `--save-temps` and reading ISA; (3) disassembling *your own* or *open-source* binaries (libggml-hip.so, librocblas.so, libamdhip64.so, RADV shaders) with llvm-objdump/RGA; (4) profiling with rocprofv3/ATT/RGP; (5) using the ISA PDFs as reference and quoting instruction semantics in your notes (the agreement restricts duplicating/redistributing the PDF itself, not using it).
- **Grey/avoid**: disassembling AMDGPU-PRO Vulkan/OpenCL (`amdvlk`-pro, `libamdocl64.so`) or the AMD Windows driver — covered by the "no reverse engineering" EULA clause. On Ubuntu Server with RADV you don't have these installed if you use `--usecase=rocm` only (skip `graphics`). Note: open-source AMDVLK (AMD's own Vulkan driver, MIT) is a *separate* open codebase and is not EULA-bound.
- Polish/EU context (**general-knowledge, not fetched this session**): Directive 2009/24/EC art. 5(3) (observe/study/test while running) and art. 6 (decompilation for interoperability) are the "applicable legislation" carve-outs the EULA points to; publishing redistributable copies of AMD's PDFs is the thing to avoid.

- Could not retrieve the current amd.com EULA text (503) nor the Linux-specific "Radeon Software for Linux" EULA PDF; the benchmark-publication clause (if any) was not verified.
- Whether `hsa-amd-aqlprofile` in ROCm 10.1.0 Ubuntu packages is built from the MIT source or still shipped as a binary blob package (`hsa-amd-aqlprofile-bin` existed in Arch for 7.1.0) **[unverified]**.

## KQ-P1. Setup checklist: ROCm 10.1 on Ubuntu Server for gfx1100, tools, RADV, RGA/RGP, umr, permissions

### Takeaway
ROCm 10.1.0 (2026-10-05) officially supports RX 7900 XTX on Ubuntu 22.04.5 / 24.04.5 / 26.04.1; install via amdgpu-install 31.60 or the `amdrocm10.1-gfx1100` apt meta-package, add yourself to `render,video`, verify with `rocminfo`/`amd-smi`. No display server is required.

### Cited Findings
- ROCm 10.1.0 release notes (2026-10-05): Radeon support on Ubuntu 26.04.1 (GA kernel 7.0), 24.04.5 (HWE 7.0), 22.04.5 (HWE 6.8); RX 7900 XTX/XT/GRE under LLVM target gfx1100; ROCm uses TheRock build/release system since 7.14; components: ROCprofiler-SDK 1.4.1 (new `--replay-mode kernel --kernel-replay-beta-enabled`, `--hip-event-trace`), ROCm Compute Profiler 3.9.0 (interactive HTML roofline; CSV backend and `--format-rocprof-output` removed, always writes rocpd), ROCgdb 16.3 — [ROCm 10.1.0 release notes](https://rocm.docs.amd.com/en/latest/about/release-notes.html)
- Install (ROCm 10.1.0 page): prerequisites `sudo apt install libatomic1 libquadmath0`; BIOS "Above 4G Decoding"; Ubuntu 24.04: `wget https://repo.radeon.com/amdgpu-install/31.60/ubuntu/noble/amdgpu-install_31.60.316000-1_all.deb && sudo apt install ./amdgpu-install_31.60.316000-1_all.deb`, then `sudo amdgpu-install --usecase=rocm,graphics --gfxversion=auto`; Ubuntu 26.04 uses `.../ubuntu/resolute/...`; apt alternative: key to `/etc/apt/keyrings/amdrocm.gpg`, repo `.../packages/ubuntu2404/`, then `apt install amdrocm10.1` or GPU-specific `amdrocm10.1-gfx1100`; `sudo usermod -a -G render,video $LOGNAME` + reboot (or udev rules); verify with `rocminfo` and `amd-smi version` — [ROCm install (10.1.0)](https://rocm.docs.amd.com/en/latest/install/rocm.html)
- Docs inconsistency: the older "install-on-linux" project pages still show amdgpu-install 7.2.4 (`amdgpu-install_7.2.4.70204-1_all.deb`, `apt install amdgpu-dkms`, `apt install rocm`) and a banner "For production use, continue to use ROCm 7.14.0"; the page itself says it moved to rocm.docs.amd.com/en/latest/install/rocm.html — [install-on-linux quick start](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/install/quick-start.html); [system requirements](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/reference/system-requirements.html)
- System-requirements page: listed Radeon GPUs "support compute workloads only, not display or graphics"; multi-GPU may need `iommu=pt`; unlisted GPUs may be community-enabled via TheRock nightly builds — [system requirements](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/reference/system-requirements.html)
- llama.cpp docs: find your target with `rocminfo | grep gfx | head -1 | awk '{print $2}'`; `HSA_OVERRIDE_GFX_VERSION=11.0.0` is only for *unsupported* RDNA3 variants (mimic gfx1100) — not needed on a real gfx1100 — [llama.cpp build.md](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)
- RGA: latest 2.15.0 (October 2026); Linux on Ubuntu 24.04, `.tgz`; offline modes (Vulkan offline, OpenGL, OpenCL, Binary Analysis) "don't need an AMD driver or GPU installed"; non-offline (DX12/DXR/live Vulkan) "require amdgpu-pro"; 2.15 adds gfx1250 (CDNA5) Binary Analysis/OpenCL, source-to-ISA correlation for code objects with debug info, AGPR shown separately — [GPUOpen RGA](https://gpuopen.com/rga/); [RGA releases](https://github.com/GPUOpen-Tools/radeon_gpu_analyzer/releases)
- RGP: V2.7, Linux build `RadeonDeveloperToolSuite-2026-05-28-1806.tgz` (release 11 June 2026); RGP requires the Radeon Developer Panel (RDP) running before launching the app — [RGP releases](https://github.com/GPUOpen-Tools/radeon_gpu_profiler/releases); [GPUOpen RGP](https://gpuopen.com/rgp/)

- umr docs sections: Wave Status (Basic Decoding, Detailed output, Kernel configurations, Full Kernel Text), Ring and IB Decoding (User Queue Packet Disassembly), Profiling, Real-time GPU Status; "umr relies on debugfs entries that newer kernels provide" — [umr docs](https://umr.readthedocs.io/en/main/); [umr build](https://umr.readthedocs.io/en/main/build.html)

### Inferences
- Minimal headless checklist (ROCm 10.1.0, Ubuntu 24.04.5): (1) BIOS Above-4G; (2) `apt install libatomic1 libquadmath0`; (3) amdgpu-install 31.60 .deb; (4) `sudo amdgpu-install --usecase=rocm --gfxversion=auto` (omit `graphics` to avoid pulling AMD's proprietary GL/VK; RADV comes from Ubuntu's `mesa-vulkan-drivers`); (5) `usermod -aG render,video`; (6) reboot; (7) `rocminfo | grep -E "Name:|gfx"`, `amd-smi version`, `ls /opt/rocm/bin | grep -E "rocprofv3|rocprof-compute|rocgdb"`, `/opt/rocm/llvm/bin/llvm-objdump --version`; (8) `apt install mesa-vulkan-drivers vulkan-tools && vulkaninfo --summary` for RADV; (9) RGA 2.15 + RDTS 2026-05-28 `.tgz` untarred into ~/tools; (10) umr from source (needs LLVM dev headers; run as root for debugfs).
- Whether `--usecase=rocm` alone vs `rocm,graphics` matters for RADV: AMD's docs say `rocm,graphics` for Radeon; for a compute-only headless box `rocm` is sufficient (**inference**, verify that `amdgpu-dkms` still installs).

## KQ-P2. Step-by-step learning path with exact commands (gfx1100)

### Takeaway
The whole loop — compile → read ISA → profile → trace → modify → A/B — works on gfx1100 with open tools; the one thing you cannot do on RDNA3 is hardware PC sampling and ATT perf-counter streaming (trace-only ATT still works).

### Cited Findings
**Step 1 — compile a small kernel and read ISA**
- hipcc example for WMMA: `hipcc --offload-arch=gfx1100 wmma_test.cpp -o wmma_test` (RX 7900 XTX/XT) — [GPUOpen WMMA on RDNA3](https://gpuopen.com/learn/wmma_on_rdna3/)
- llama.cpp's own CMake option `GGML_HIP_EXPORT_METRICS` appends `-Rpass-analysis=kernel-resource-usage --save-temps` to `CMAKE_HIP_FLAGS` (ggml/src/ggml-hip/CMakeLists.txt line 116-117, commit 2744e48d, 2026-10-17) — i.e. the two flags AMD's own compiler uses to emit per-kernel VGPR/SGPR/LDS/occupancy remarks and keep `.s` files — local clone at /tmp/claude-0/-home-user-KERNEL/2fec5121-746d-5a8c-9207-83ad66dddd8f/scratchpad/re_amd/llama_cpp/llama.cpp ([upstream](https://github.com/ggml-org/llama.cpp))
- LLVM `.s` output contains human-readable resource comments like `; NumVgprs: 41` and `; TotalNumSgprs: 80` and `.amdhsa_kernel` blocks with `.amdhsa_next_free_vgpr` / `.amdhsa_next_free_sgpr` directives — [LLVM call-graph-register-usage test](https://llvm.googlesource.com/llvm-project/+/f20e2829dfdd25bd2ea2cbef1617652878747cb5/llvm/test/CodeGen/AMDGPU/call-graph-register-usage.ll); [LLVM MC user-sgpr-count test](https://rust.googlesource.com/rust-lang/llvm-project/+/2a2ea6b49e79325e0d10d33fac2b10ea3bebcc7c/llvm/test/MC/AMDGPU/user-sgpr-count.s)
- LLVM AMDGPUUsage, gfx1100: `amdgpu11.00`, family `gfx11-generic`, dGPU (RX 7900 XTX/XT); target features `cumode`, `wavefrontsize64` ("When disabled native wavefront size 32 is used"), architected flat scratch, packed work-item IDs; "Not all VGPRs can be used on" gfx1100/1101/1151 — [LLVM AMDGPUUsage](https://llvm.org/docs/AMDGPUUsage.html)

**Step 2 — llama.cpp HIP build and finding the Q4_K mmvq kernel**
- Linux HIP build: `HIPCXX="$(hipconfig -l)/clang" HIP_PATH="$(hipconfig -R)" cmake -S . -B build -DGGML_HIP=ON -DGPU_TARGETS=gfx1100 -DCMAKE_BUILD_TYPE=Release && cmake --build build --config Release -- -j 16`; `GPU_TARGETS` optional (omit = all GPUs in system); if "cannot find ROCm device library", set `HIP_DEVICE_LIB_PATH` to the dir containing `oclc_abi_version_400.bc`; `HIP_VISIBLE_DEVICES` selects GPUs — [llama.cpp build.md](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md)
- ggml-hip CMake (local clone, 2026-10-17): `AMDGPU_TARGETS` is forwarded to `GPU_TARGETS` → `CMAKE_HIP_ARCHITECTURES`; options `GGML_HIP_GRAPHS`, `GGML_HIP_NO_VMM`, `GGML_HIP_MMQ_MFMA` (off → `GGML_HIP_NO_MMQ_MFMA`), `GGML_HIP_RCCL`, `GGML_HIP_EXPORT_METRICS`; debug flags `-g -Xarch_device -O2 -Xarch_host -O0`; **no `GGML_HIP_ROCWMMA_FATTN` option exists any more in master** (grep over ggml/CMakeLists.txt, ggml-hip/CMakeLists.txt, docs/build.md returned nothing) — local clone (ggml/src/ggml-hip/CMakeLists.txt)
- The decode GEMV kernel is `template <ggml_type type, int ncols_dst, bool has_fusion, bool small_k=false, bool halve_iters=false> __launch_bounds__(calc_nwarps(...)*ggml_cuda_get_physical_warp_size(), 1) static __global__ void mul_mat_vec_q(...)` in ggml/src/ggml-cuda/mmvq.cu (line 621-623); Q4_K uses `vec_dot_q4_K_q8_1` and `VDR_Q4_K_Q8_1_MMVQ`; a MoE variant `mul_mat_vec_q_moe` exists (line 882); `ggml_cuda_get_physical_warp_size()` = 32 on RDNA (wave32) — local clone (ggml/src/ggml-cuda/mmvq.cu)
- ggml-cuda/common.cuh: `GGML_CUDA_CC_RDNA3 = OFFSET_AMD + 0x1100 // RX 7000, minimum for WMMA`; `GGML_CUDA_CC_RDNA3_5 = +0x1150`, `RDNA4 = +0x1200`; code paths under `#if defined(GGML_USE_HIP) && (defined(RDNA4) || defined(RDNA3))` — local clone (ggml/src/ggml-cuda/common.cuh lines 83-94, 280, 716)
- llvm-objdump (ROCm 7.x LLVM docs) has an option to "display the content of the LLVM offloading section and extract Clang offload binaries into code objects" (upstream text: "LLVM offloading sections and HIP offload bundles"); older HIP docs describe `roc-obj-ls` (list code-object URIs in host executables) and `roc-obj-extract` — [ROCm llvm-objdump](https://rocm.docs.amd.com/projects/llvm-project/en/docs-7.14.0/LLVM/llvm/html/CommandGuide/llvm-objdump.html); [HIP obj_tooling (5.0.2)](https://github.com/ROCm-Developer-Tools/HIP/blob/rocm-5.0.2/docs/markdown/obj_tooling.md)

**Step 3 — rocprofv3 kernel trace / stats on llama-bench**
- `rocprofv3 --kernel-trace --output-format csv -- <app>` → `<pid>_kernel_trace.csv`; `rocprofv3 --stats --hip-trace --output-format csv -- <app>` → `hip_api_stats.csv`, `domain_stats.csv`; `-S` per-tracing-type summary (stderr), `-D` per-domain, `--summary-groups 'MEMORY_COPY|HIP_API'`, `--summary-output-file`; default output format is now `rocpd` (CSV/PFTrace/OTF2 direct output deprecated) → `rocpd convert -i <file>_results.db --output-format csv`; `--list-avail` lists counters — [rocprofv3 docs 10.1.0](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/docs-10.1.0/how-to/using-rocprofv3.html)
- llama-bench flags: `-m <gguf>`, `-p 512` (prompt), `-n 128` (gen), `-pg pp,tg`, `-d` depth, `-b 2048`, `-ub 512`, `-ctk/-ctv f16`, `-ngl -1`, `-fa on|off|auto`, `-sm none|layer|row|tensor`, `-mg`, `-dev`, `-r 5` repetitions, `-o csv|json|jsonl|md|sql`, `--list-devices`, `--no-warmup` — local clone (tools/llama-bench/README.md)

**Step 4 — counters / PC sampling / ATT on gfx1100**
- Counters: `rocprofv3 --pmc SQ_WAVES GRBM_COUNT GRBM_GUI_ACTIVE -- <app>`; each extra `--pmc` = another pass in `pass_n/`; results in `pmc_n/counter_collection.csv`; **RDNA3/RDNA4 caveat**: `AUTO` perf level disables PMC in some blocks → `sudo /opt/rocm/bin/amd-smi set --gpu <N> --perf-level STABLE_STD` before profiling, restore with `--perf-level AUTO`; derived-counter examples list gfx1100/1101/1102 for `GRBM_GUI_ACTIVE_SUM`; beta kernel replay: `--replay-mode kernel --kernel-replay-beta-enabled` (not combinable with `--att`, PC sampling, `--spm`) — [rocprofv3 docs 10.1.0](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/docs-10.1.0/how-to/using-rocprofv3.html)
- PC sampling: host-trap only on CDNA2/3/4 (MI210…MI355X), stochastic only on CDNA3/4 (gfx942+); MI100 unsupported; **no Radeon/RDNA target is listed** — [PC sampling docs 10.1.0](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/docs-10.1.0/how-to/using-pc-sampling.html)

## KQ-P3. Pitfalls (HSA_OVERRIDE, driver/ROCm mismatch, rocprof-compute on RDNA, ATT on consumer GPUs, headless, GPU resets)

### Takeaway
On a genuine gfx1100 no override is needed; the real risks are stale install docs (7.x vs 10.1), profiler features that silently don't apply to RDNA, and MES/"ring gfx timeout" resets that wipe VRAM.

### Cited Findings
- `HSA_OVERRIDE_GFX_VERSION=11.0.0` exists only to make *unsupported* RDNA3 parts mimic gfx1100; RX 7900 XTX is natively gfx1100 — [llama.cpp build.md](https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md); [ROCm 10.1.0 release notes](https://rocm.docs.amd.com/en/latest/about/release-notes.html)
- Two parallel doc sets exist: "install-on-linux" (still amdgpu-install 7.2.4 / "use ROCm 7.14.0") vs the new rocm.docs.amd.com/en/latest/install/rocm.html (amdgpu-install 31.60 / ROCm 10.1.0) — mixing them yields driver/userspace mismatches — [old quick start](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/install/quick-start.html); [new install page](https://rocm.docs.amd.com/en/latest/install/rocm.html)
- ROCm 7.10 preview notes: "not intended for production workloads"; "no upgrade path from existing production releases" — preview streams don't upgrade cleanly — [ROCm 7.10.0 release notes](https://rocm.docs.amd.com/en/7.10.0-preview/about/release-notes.html)
- rocprof-compute 10.1.0 lists no discrete RDNA3; RDNA model page is gfx115x-only — [compatible accelerators](https://rocm.docs.amd.com/projects/rocprofiler-compute/en/docs-10.1.0/reference/compatible-accelerators.html)
- ATT on gfx1100 is "Trace-only"; perf-counter streaming options are gfx9-only; `--att-shader-engine-mask` too high → packet loss/full buffer; empty `stats_*.csv` = no waves on target CU — [thread trace docs](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/docs-10.1.0/how-to/using-thread-trace.html)
- PMC on RDNA3/RDNA4 needs `amd-smi set --perf-level STABLE_STD` or some blocks return nothing under `AUTO` — [rocprofv3 docs](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/docs-10.1.0/how-to/using-rocprofv3.html)
- PC sampling: CDNA only — [PC sampling docs](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/docs-10.1.0/how-to/using-pc-sampling.html)
- Headless: ROCm's listed Radeon GPUs "support compute workloads only, not display or graphics" in that doc set — no X/Wayland is implied; `MESA_VK_WSI_HEADLESS_SWAPCHAIN` forces headless swapchains for Vulkan — [system requirements](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/reference/system-requirements.html); [Mesa envvars](https://docs.mesa3d.org/envvars.html)
- GPU resets on 7900 XTX: kernel log pattern "job timeout on ring gfx_0.0.0" → "GPU reset begin!" → "MES might be in unrecoverable state, issue a GPU reset" → mode1 reset → "VRAM is lost due to GPU reset!" — [drm/amd issue 3056](https://gitlab.freedesktop.org/drm/amd/-/issues/3056); [issue 2421](https://gitlab.freedesktop.org/drm/amd/-/issues/2421)
- A llama-server hang on RX 7600 XT (gfx1102) under ROCm/TheRock showed "cp queue preemption failed / Failed to evict process queues / MODE1 reset" while the same build on Vulkan/RADV ran clean — [ROCm/TheRock issue 5793](https://github.com/ROCm/TheRock/issues/5793)
- amdgpu module params: `gpu_recovery` "Enable GPU recovery mechanism, (1 = enable, 0 = disable, -1 = auto)"; `lockup_timeout` = scheduler timeout in ms, default 2000 ms, per-queue values for GFX/Compute/SDMA/Video, negative = infinite — [amdgpu_drv.c](https://raw.githubusercontent.com/torvalds/linux/master/drivers/gpu/drm/amd/amdgpu/amdgpu_drv.c)
- Multi-GPU boxes may need `iommu=pt` — [system requirements](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/reference/system-requirements.html)

### Inferences
- With both an RX 7900 XTX and an RTX 5060 Ti in one box, use `HIP_VISIBLE_DEVICES=0` / `ROCR_VISIBLE_DEVICES` and `GGML_VK_VISIBLE_DEVICES` to pin llama.cpp to the AMD card; Vulkan will enumerate both GPUs.
- For long-running kernels under a debugger/ATT, raise `amdgpu.lockup_timeout` (e.g. `amdgpu.lockup_timeout=10000` or `-1` for compute queue) to avoid the 2 s watchdog firing during single-stepping with rocgdb.
- After any "VRAM is lost" reset the llama.cpp process must be restarted (weights gone) — keep `dmesg -w` open in a second tmux pane while experimenting.

### Gaps
- No primary source on whether `amdgpu.gpu_recovery=0` helps or hurts ROCm debugging on RDNA3.
- No official AMD statement about rocprof-compute discrete-RDNA3 status beyond its absence from the table.

## KQ-P4. Learning resources ranked for ISA-level RDNA understanding

### Takeaway
Start with AMD's own RDNA3 ISA guide + the RDNA architecture deck, use the ROCm profiler docs' RDNA chapters for the performance model, and read ACO (Mesa) and llama.cpp mmvq.cu as "annotated real kernels".

### Cited Findings (ranked)
1. RDNA3 ISA Reference Guide (15-Aug-2023, 600 pp): program state, wave execution models, memory hierarchy interaction, instruction encodings; "most useful for … compiler writers and shader optimizers" — [PDF](https://gpuopen.com/download/rdna3-shader-instruction-set-architecture-feb-2023.pdf); [GPUOpen announcement](https://gpuopen.com/rdna3-isa-guide-now-available/); also RDNA3.5 and RDNA4 guides — [ISA hub](https://gpuopen.com/amd-isa-documentation/)

3. GPUOpen "Occupancy explained" (VGPR/SGPR/LDS limits, wave32 vs wave64 on RDNA) — [article](https://gpuopen.com/learn/occupancy-explained/)
4. GPUOpen "How to accelerate AI applications on RDNA 3 using WMMA" (intrinsics, fragment layouts, hipcc command) — [article](https://gpuopen.com/learn/wmma_on_rdna3/)
5. ROCm Compute Profiler RDNA chapters (WGP metrics, System Speed-of-Light, GL0/GL1/GL2, SPI, GRBM) — written for gfx115x but the block model is RDNA3 — [WGP](https://rocm.docs.amd.com/projects/rocprofiler-compute/en/latest/conceptual/rdna/wgp.html); [RDNA performance model](https://rocm.docs.amd.com/projects/rocprofiler-compute/en/docs-10.1.0/conceptual/rdna/rdna-performance-model.html)
