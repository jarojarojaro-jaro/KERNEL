## Confirmed

1. "AMD publishes machine-readable XML ISA specs for RDNA1-4 (incl. 3.5) and CDNA1-5 with a C++ IsaDecoder API (isa_spec_manager); page updated August 2026 added amdgpu_isa_cdna5.xml and schema v1.2.0." — gpuopen.com/machine-readable-isa lists CDNA 5 (MI450) … CDNA 1 and RDNA 4 / 3.5 / 3 / 2 / 1, says "The AMD GPU IsaDecoder API makes it easy to parse the specification XML files…", links isa_spec_manager, and the "What's new" box is marked "Updated August 2026" with "`amdgpu_isa_cdna5.xml` is a new XML specification for CDNA5" and "New XML schema v1.2.0 (CDNA5 only)". The isa_spec_manager README independently confirms IsaDecoder and the experimental `explorer::Spec` API.

2. "RDNA3 ISA (Feb 2023) documents VOPD hard rules: 4 VGPR banks indexed by SRC[1:0], each with a 3-read-port cache; SRCX0/SRCY0 and VSRCX1/VSRCY1 must be in different banks, dest VGPRs one even one odd, wave32 only, no DPP; LDS is 128 KB per WGP as 64 banks of 512x32-bit two-port RAM, 64 KB max per workgroup; S_DELAY_ALU packs InstID1[4]/Skip[3]/InstID0[4] with codes 1-4 VALU, 5-7 transcendental, 9-11 SALU cycles." — All technical content verified verbatim in the PDF text (§7.6 "There are 4 VGPR banks (indexed by SRC[1:0]), and each bank has a cache… 3 read ports…", "SRCX0 and SRCY0 must use different VGPR banks; VSRCX1 and VSRCY1 must use different banks", "Dest VGPRs: one must be even and the other odd", "Must not use DPP", "Must be wave32"; §12.1 "128kB … 64 banks … 512x32 two-port RAM … up to 64kB"; "S_DELAY_ALU InstID1[4], Skip[3], InstID0[4]"; Table 19 codes 1-4 / 5-7 / 9-11). Caveat on the date label: see "Refuted" item A — the PDF served at the feb-2023 URL is the 15-August-2023 revision.

3. "RDNA4 ISA (dated 7-April-2025) adds dynamic VGPR allocation via S_ALLOC_VGPR (wave32 only, 16/32-VGPR blocks, up to 8 blocks), split barriers S_BARRIER_SIGNAL/S_BARRIER_WAIT, new counters LOADcnt/STOREcnt/DScnt(6b)/KMcnt(5b)/SAMPLEcnt/BVHcnt with S_WAIT_LOADCNT_DSCNT, scalar prefetch instructions, FP8/BF8 WMMA and SWMMAC sparse 16x16x32 forms, and relaxes the VOPD bank rule to allow the same VGPR in both SRC0 slots." — PDF title page "7-April-2025"; "Dynamic VGPRs are supported only for wave32, not wave64"; "allocated/deallocated in blocks of 16 or 32 VGPRs (configurable)"; "Waves may allocate up to a maximum of 8 blocks"; S_BARRIER_SIGNAL / S_BARRIER_WAIT present; counter table LOADcnt 6 / STOREcnt 6 / DScnt 6 / KMcnt 5 / SAMPLEcnt 6 / BVHcnt 3; S_WAIT_LOADCNT_DSCNT (opcode 72); S_PREFETCH_INST / _PC_REL / S_PREFETCH_DATA / _PC_REL; V_WMMA_F32_16X16X16_{FP8,BF8}_{FP8,BF8} and V_SWMMAC_*_16X16X32_* table; "SRC0x and SRC0y must come from different VGPR banks (bank# = SRC % 4), or be the same VGPR and same sized operand".

4. "LLVM's GFX11SpeedModel encodes the compiler's latency beliefs for gfx1100: 32-bit VALU/FMA 5, 64-bit 6, transcendental 10, quarter-rate 8, FP64 38, int mul 8, LDS 20, SALU 2, SMEM 20, VMEM 320, barrier 2000 ('latency = 1/(ops/cycle) + 1 VGPR-read stall'); GFX12 lowers trans to 9 and quarter-rate to 6; gfx1250 WMMA 16x16x128 F16 runs in 8 cycles." — SISchedule.td on GitHub main: every value matches (Write32Bit 5, WriteFloatFMA 5, Write64Bit 6, WriteTrans32 10, WriteQuarterRate32 8, WriteDouble 38, WriteIntMul 8, WriteLDS 20, WriteSALU 2, WriteSMEM 20, WriteVMEM 320, WriteBarrier 2000; comments "The latency values are 1 / (operations / cycle)." / "Add 1 stall cycle for VGPR read."); GFX12SpeedModel WriteTrans32 9, WriteQuarterRate32 6; comment "16x16x128 FP8/BF8 and F16/BF16 run in 8 cycles" with WriteXDL2PassWMMA = 8. Local clone agrees.

5. "LLVM exposes scheduler control: llvm.amdgcn.sched.barrier masks (0x2 VALU, 0x4 SALU, 0x8 MFMA/WMMA, 0x20 VMEM read, 0x40 VMEM write, 0x100/0x200 DS read/write, 0x400 TRANS, 0x800 LDSDMA), sched.group.barrier(mask,size,syncID) pipelines, iglp_opt strategies 0-3, and 'amdgpu-waves-per-eu'='m,n' (clang amdgpu_waves_per_eu) as an occupancy hint overridden by amdgpu-flat-work-group-size." — AMDGPUUsage.html: mask table 0x0000–0x0800 exactly as stated; sched.group.barrier takes Mask/Size/SyncID; iglp.opt strategies 0–3 as described (experimental); "amdgpu-waves-per-eu" is "an optimization hint" and "the implied occupancy bounds by the workgroup size takes precedence". clang spelling `amdgpu_waves_per_eu` confirmed in local clang/include/clang/Basic/Attr.td (AMDGPUWavesPerEU).

6. "Measured on RX 7900 XTX (Jan 2023): common FP32 ops have 5-cycle latency, INT32 multiply runs at ~1/4 FP32 rate, reciprocal at 1/4 rate, dual issue was clearly observed only for v_dual_add_f32 (FMA rarely dual-issued, INT32 has no VOPD form), scalar cache 16 KB/15.4 ns, vector L0 32 KB 32-way, L1 256 KB 16-way, L2 6 MB 16-way, Infinity Cache 96 MB, LDS 128 KB per WGP as two 64 KB blocks of 32 banks." — Chips and Cheese article dated Jan 07, 2023: "Common FP operations execute with 5 cycle latency", INT32 mul "around a quarter of FP32 rate", reciprocal "quarter rate", v_dual_add_f32 the only clear dual-issue case, few FMA dual-issues, "lack of VOPD instructions for INT32", "16 KB, 4-way set associative scalar cache" with 15.4 ns, L0 32 KB/CU 32-way, L1 256 KB 16-way, L2 6 MB 16-way, Infinity Cache 128 → 96 MB, LDS 128 KB/WGP "Each 64 KB block contains 32 banks".

7. "RDNA4 WMMA (GPUOpen, 2025-07-11) removes RDNA3's lane duplication of A/B (each of 32 lanes holds 8 elements, 16x16 tile covered once), changes the VGPR layout so RDNA3 code is not backward compatible, uses _gfx12 intrinsics, and raises theoretical matrix throughput to FP16/BF16 1024 and INT8 2048 FLOPS/clock/CU vs 512/512 on RX 7900 XTX." — Page "Originally posted: July 11, 2025"; table FP16 512→1024, BF16 512→1024, I8 512→2048 (RX 7900 XTX vs RX 9070 XT); "we needed to duplicate some elements for A and B, but it is removed for RDNA 4"; "it does not have backward compatibility"; intrinsics "have postfix `_gfx12`" e.g. `__builtin_amdgcn_wmma_f32_16x16x16_f16_w32_gfx12`.

8. "The documented standalone-assembly path is a .s with code + .amdhsa_kernel descriptor (required .amdhsa_next_free_vgpr/.amdhsa_next_free_sgpr) + .amdgpu_metadata YAML; in practice people run hipcc -save-temps, then clang -x assembler -target amdgcn-amd-amdhsa -mcpu=<gfx> -c on the .s, and must add the lld link step (hipcc -save-temps -v shows it); inline asm must use explicit v/s constraints and contain only instructions." — Discourse thread (May 3, 2024): OP ran `hipcc -save-temps -O1 --amdgpu-target=gfx801 …` then `clang++ -x assembler -target amdgcn--amdhsa -mcpu=gfx801 -c square.kernel.s`; link failed with "Relocations in generic ELF (EM: 224)"; kuhar: "it seems like an `lld` linker invocation is missing" and "-save-temps -v … will print the intermediate commands"; arsenm: "Inline asm is expected to only include instructions"; jhuber6 suggested `v`/`s` constraints. `.amdhsa_next_free_vgpr` marked "Required" in AMDGPUUsage.rst (local, line 21909). Minor precision: the thread's exact triple spelling was `amdgcn--amdhsa` (with clang++), not `amdgcn-amd-amdhsa`; both are accepted by clang, so the claim stands.

## Refuted with corrections

A. (extra, from note lines 11/12/18 and the claim-2 label) "RDNA3 ISA (Feb 2023)" / "RDNA3 Feb-2023 PDF has 600 pages" — The PDF actually served at https://gpuopen.com/download/rdna3-shader-instruction-set-architecture-feb-2023.pdf carries the title-page date "15-August-2023" (pdfinfo CreationDate 2023-08-16). The *URL* says feb-2023 (first publication, Phoronix Feb 2023), but the document the note quotes is the August-2023 revision. Correction: cite it as "RDNA3 ISA Reference Guide, rev. 15-August-2023 (URL still named feb-2023)".

B. (extra, note line 111) "GPUOpen's 'Hsaco from assembly' post (`gpuopen.com/?p=3532`) states 'The ability to write code in assembly is essential to achieving the best performance for a GPU program'" — WebFetch of https://gpuopen.com/?p=3532 returns the GPUOpen homepage; no post titled "Hsaco from assembly" and no such sentence is present. The cited URL does not support the quote. Correction: drop the quote or find the real page (the post may have been retired; the ROCm/LLVM-AMDGPU-Assembler-Extra repo cited alongside it does exist).
