1. **libcuda's RM escape codes are public: NV_ESC_RM_ALLOC 0x2B, NV_ESC_RM_CONTROL 0x2A, NV_ESC_RM_MAP_MEMORY 0x4E, NV_ESC_RM_VID_HEAP_CONTROL 0x4A, etc., so an strace of a CUDA process can be fully decoded (open-gpu-kernel-modules main, 2026-10-17).**

   - Independent: strace-devel 2020 patch "ioctl: add symbolic translations for Nvidia ioctl codes" exists (lists.strace.io); Quarkslab post confirms "using the header files provided in the kernel modules repository as a basis, it's possible to make direct ioctl calls".
   - Caveat (already stated in the note's Inferences): "fully decoded" applies to the escape numbers and parameter structs; `NV_ESC_RM_CONTROL` command semantics live in the `ctrl*.h` headers and pushbuffer contents are not visible via ioctl at all.

## Refuted with corrections

9. **(Extra, note lines 107 and 224) "CCCL lists `setmaxnreg.inc.sync.aligned.u32 // PTX ISA 80, SM_90a, SM_100a`" and the inference "`setmaxnreg` is not listed for sm_120 in CCCL (only SM_90a/SM_100a), so Hopper-style warp-specialised register rebudgeting likely does not apply".**
   - The cited CCCL page (nvidia.github.io/cccl/unstable/libcudacxx/ptx/instructions/setmaxnreg.html, fetched 2026-10-17) reads: "setmaxnreg.inc.sync.aligned.u32 imm_reg_count; // PTX ISA 80, SM_90a, SM_100a, SM_100f, SM_103a, SM_103f, SM_107a, SM_107f, SM_110a, SM_110f, SM_120a, SM_120f, SM_121a, SM_121f" (same list for `.dec`). SM_120a and SM_120f ARE listed. Correction: `setmaxnreg` is available on sm_120a/sm_120f per CCCL; the inference that warp-specialised register rebudgeting does not apply to the RTX 5060 Ti should be dropped (the CUTLASS SM120 kernels are themselves "TmaWarpSpecialized").
