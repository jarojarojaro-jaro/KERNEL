# Brief: GGML_CUDA_MMVQ_OCC — register cap (min blocks per SM) for the multi-column MMVQ on NVIDIA (bit-exact, default off)

## Goal
Speed up the speculative-decoding verify step of Qwen3.8-27B UD-Q6_K_M on an RTX 3090 (Ampere sm_86, 82 SMs,
936 GB/s, 64K regs/SM, max 16 blocks and 48 warps per SM). The verify batch is 5 tokens (MTP draft n=4 + 1), so each
weight matrix runs through `mul_mat_vec_q<type, ncols_dst=5, ...>` (multi-column path, `use_multi`). Profile (nsys,
2026-10-20): `mul_mat_vec_q` is 88% of GPU busy time in the decode loop. Model bytes by type: Q6_K 13.8 GB (60%),
Q8_0 5.9 GB (25%), Q5_K 3.3 GB (14%).

- `calc_nwarps()` (~1260) and `calc_rows_per_block()` (~1433): on NVIDIA (`MMVQ_PARAMETERS_GENERIC`) launches with
  ncols_dst 5..8 use **2 warps (64 threads) per block, 2 rows per block**; 2..4 columns: 4 warps, 2 rows.

## Hypothesis
The 5-column kernels are register-limited to 12–16 warps per SM (3–4 per SM sub-partition) — too few loads in flight
to saturate GDDR6X. Capping registers via `__launch_bounds__(64, minBlocks)` (e.g. minBlocks 8 → ≤128 regs,
10 → ≤102, 12 → ≤85) raises resident warps. It changes only register allocation / instruction scheduling in ptxas, not
the arithmetic or its order (no fast-math; FMA contraction is decided before ptxas), so outputs are bitwise identical.
On RDNA3 the same idea gave nothing (report 24n) — sm_86 has a different latency-hiding model, so we measure.

## Change
1. Env `GGML_CUDA_MMVQ_OCC` = minimum blocks per SM target, accepted values 8, 10, 12 (unset/other = today's kernel;
   default OFF, code path unchanged when unset). Applies only on NVIDIA (`!GGML_USE_HIP`), only to `ncols_dst` 4..6
   (keep compile time bounded), only to these types: Q6_K, Q5_K, Q4_K, IQ4_XS, Q8_0, and to both the plain and the
   fused (`has_fusion`) instances that the 5-column verify uses.
2. Implementation: new template parameter (e.g. `int min_blocks`, default 0 = today's `MMVQ_LAUNCH_BOUNDS`) on
   `mul_mat_vec_q`; for `min_blocks > 0` on CUDA emit `__launch_bounds__(nwarps*warp_size, min_blocks)`. Runtime
   selection in the host switch reads the env once (static). If a per-type value is better, also allow
   `GGML_CUDA_MMVQ_OCC_<TYPE>` overrides — optional, only if cheap.
3. Bit-exact: nwarps, rows per block, vdr, blocks_per_iter, thread→(kbx,kqs) mapping, and the reduction must be
   untouched. Put a comment in the style of the existing `[GGML_CUDA_MMVQ_N1_ROWS]` comment explaining why.
4. Do not touch HIP/RDNA tables or any other file except a declaration if strictly needed.

## Constraints
- Lossless: env unset → generated code identical to today (same instances, same attributes). Env set → bitwise same
  outputs. No GPU, no llama-server, no benchmarks.
