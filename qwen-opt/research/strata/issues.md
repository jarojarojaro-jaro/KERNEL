## 2. How the maintainer handles performance claims (methodology standards)

Pattern visible across dozens of threads — the bar a change must clear:

1. **Exactness first, speed second.** Default-path changes must keep output byte-identical ("every change goes through our identity gate (byte-identical output on four models) and a speed A/B before it ships", P#284, P#321). Tools: `STRATA_DUMP_FIRST_LOGITS` (first-token logits), parity ctests per kernel, a deterministic config (`STRATA_IQ_MT_MIN=1 --pcie-frac 0 --adapt-every 0 --prompt-cache 0`).
2. **Anything that changes bits is opt-in**, regardless of gain: P#186 (HC read v3, +2-4% decode) "it changes bits and is on by default… make it opt-in"; P#260/P#313 RDNA3 WMMA GEMM (fp16 accumulate/round-toward-zero vs hipBLAS) → opt-in `STRATA_WMMA_GEMM=1`; P#820 dense MMQ → opt-in (KL 0.008–0.09 vs default); P#1570 gfx12 int8-WMMA experts stayed opt-in because IQ3_XXS KL (0.00388) was not ≤ MMQ's (0.00340); P#2020 F16 experts opt-in.
3. **Quality gate for bit-changing defaults** = teacher-forced KL vs same engine, run-to-run KL floor, PPL ratio, HumanEval/reasoning set. Example P#1668: `STRATA_ROUTE_TAIL_SKIP=7` made default with "teacher-forced KL 0.003-0.006 mean (the run-to-run floor is 0.0007), perplexity x1.005-1.011"; the companion `ROUTE_PRIOR` (+26-28% combined) rejected for "about three times the KL".
4. **Speed A/B = interleaved/alternating pairs, fresh engine per arm, medians, "faster in k of n pairs".** Standard asks: "5 alternating pairs" (P#500), "10+ pairs, medians" (P#981), "ten interleaved pairs" (P#981 refile). Typical report: "+15.6% … 5 interleaved pairs each, faster in 5 of 5" (P#1668); "8 interleaved pairs… faster in 8 of 8" (P#1656).
5. **No measured gain ⇒ no merge, even if bit-exact or "hygiene".** P#500 (parallel CPU quant): "Three independent measurements (gfx1100, RTX 5080, RTX 5090) put the quantize phase at 0.4-0.5% of a round, and none saw a gain". P#139 (pre-Ampere BF16 SGEMM): −0.17% e2e ⇒ stay on cuBLAS. P#407 `--adapt-tuned`: "the round time did not move… we'd rather not add a mode that changes tokens without a measured gain". P#744 gfx1100 decode autotuner: defaults already won (<1%) ⇒ closed; only the `--spec-min-p 0.70` (+10%) finding kept.
6. **Profile-based skepticism of big claims.** P#500 claimed +78%; maintainer: "a quantization loop of a few hundred microseconds per layer would not explain +78%, so the per-round breakdown matters" — asked for `STRATA_VERIFY_PROFILE=1` both arms; contributor then admitted the +78% was a cache-size change measured in the same session.
7. **Single-reporter results don't flip defaults on hardware the maintainer lacks.** I#1386 (gfx1100 `STRATA_PF_GEMM` +7%): "We will not turn it on by default for gfx1100 on one reporter's two-card measurement; if a second 7900 XTX / XT owner confirms the +7% we will add gfx1100 to the per-arch defaults". I#1705: "We do not make it a default (we cannot reproduce…)". Per-arch default tables exist (`arch_defaults.cpp`; gfx1151 and gfx12 rows, commit dd106e7d).
8. **When a default backfires, flip to the safe side fast.** I#2010/I#1964: `STRATA_ADAPT_OVERLAP` default-on in 0.1.43 cost 19–26% on several boxes (−65% on one), gained 5–10% on an A4000 and +6% on P100; 0.1.43.1 made it opt-in on every backend: "the safe default is the one that cannot cost you speed".
9. **Contributor PRs are re-implemented, split, and gated** rather than merged: P#646/P#783 (stuchapin909, +39–72% claims) were "split and ported into 0.1.40… Each has its own kill switch"; fused norm+RoPE kept off on HIP because `rope_parity` check 6 failed on gfx1151 (~7% of elements differ).
10. **Honest "we measured it, here's the real number" in docs.** I#432: release-note +12% router gain wasn't reproducible inside a 12–20% spread; maintainer: "your repeated A/B/A/B (+1-4% inside a 12-20% spread) is the better measurement"; `docs/AMD_HIP.md` now carries both numbers (docs/AMD_HIP.md:332-336).
11. Maintainer's own noise admissions: "the same question twice gave 62 then 78 tok/s here" (first request after start slower while expert cache adapts; code decodes 20-30% faster than prose because of draft acceptance) I#119; R9700 "shared box was too noisy… decode swings 4-100 tok/s between runs of the same arm because other jobs share the CPU" I#1705.

## 3. Community methodology & noise levels reported

- **I#432** (R9700): within-run spread **12–20%** on decode; 4K prompt speed landed at one of two levels per server start (~1,545 or ~1,700) on ROCm 7.10 — bimodal per start, gone on ROCm 7.14 (five starts 1,973–2,010).
- **I#816 / Solear**: with the shared-expert stream fork on, decode "flips between a slow and a fast mode" per engine start (slow on 7 of 15 starts: 75–77 vs ~100 tok/s), stable ±2% within a start.
- **P#745** (7900 XTX): cold→warm decode climbs **~+35%** on both ROCm stacks; "one-shot cells under-measure serving by 25–35%".
- **I#2227**: box drifts ±4–6% across boots ⇒ interleave arms within one session.
- **I#2010 thread** (Krypto-Whitehat): "Only one variable may differ between the two runs"; a version-vs-version comparison answers a different question than a switch A/B. mmbeanz used 40 requests + p-values/CI (decode Δ −3.4%, p=0.39) — and was then shown the flag was force-off on layer splits (check the switch actually engages).
- **P#783 thread** (q8atnight): "+5–8% in 3-run rounds… more samples ate the ordering effect" → +3.7%, not significant (n=10/side, pooled sd ≈5.8).
- Engagement checks: confirm env reached the process (`/proc/<pid>/environ`, I#432); objdump count of `v_wmma` instructions to prove the fast path compiled (P#786: "exactly 32 `v_wmma_f32_16x16x16_f16`… no fallback can masquerade"); print which arm ran once at startup (P#228); `STRATA_HIPBLASLT_VERBOSE=1` fallback counts (P#1289).
- Silent fallbacks found repeatedly: `STRATA_PF_FUSED` inert under `STRATA_PREFILL_MMQ=0` (I#1180 comment); without `STRATA_HIP_WMMA=1` the gfx11 prompt attention silently uses the old kernel (I#1386); hipBLASLt table version mismatch ⇒ silent plain-hipBLAS fallback (I#505, I#1389, P#745); `STRATA_WMMA_GEMM=0` turned WMMA *on* (presence test, P#313); `STRATA_WMMA_GFX11` host pass doesn't define `__gfx1100__` so WMMA got compiled out (P#260).
- Community tooling: `tools/strata_bench.py` / `bench.sh` (0.1.43) suite (I#713), external `strata-bench` schema + validator + dashboard https://brenoperucchi.github.io/strata-bench/ (I#713).

## 4. AMD-specific findings

### 4.1 gfx1100 / RX 7900 XTX
- **hipBLASLt tuning tables (per-shape solution index, version-pinned)** are the biggest single prefill lever for Strata's FP16 dense GEMMs: 7900 XTX 128K prefill **921 → 1,615–1,687 tok/s (+75–82%)** with a matching `gfx1100-hipblaslt-100500` table (P#745, I#505); 622 → 1,088 on W7800 (I#505); "+42–59% prompt speed on a 7900 XTX" when first tuned (P#121); small-T expert GEMM rows **+31.9%** on a 3,151-token prompt (642 fallbacks → 0, P#1289). Loader refuses version mismatch (silent ~45% loss, I#1389). Counter-examples: R9700 table +0.4% e2e despite per-GEMM 0.91–2.07× (I#432); gfx1201/100201 table neutral after re-measure (I#979 — first claimed −17%, corrected as noise); 2× 7900 XTX self-calibrated 100201 table e2e-neutral "my dense GEMMs are WMMA-dominated" though single shapes up to 5.46× (I#1386).
- **RDNA3 WMMA fragment layout** (unsuffixed `v_wmma_f32_16x16x16_f16`, wave32) differs from gfx12 on all three operands: A `A[l&15][i]`, B `B[i][l&15]`, D `D[(l>>4)+2i][l&15]`; gfx12-style packing compiles but fails parity at ~30× (P#786, citing AMD Matrix Instruction Calculator).
- **WMMA prompt attention** (int8 KV → fp16 WMMA): kernel 4.05–5.12× vs FP32 fallback; e2e prefill **+22.8% @128K (5/5 pairs), +17.9% @32K**; the FP32 fallback had been 25.6–26.9% of prefill GPU time (P#786; confirmed +29.5% PP by Jlauti, −17% wall by 2jztricks). Superseded by maintainer's own gfx11 kernel in 0.1.40 (`STRATA_HIP_WMMA=1`). On 7900 XT `STRATA_HIP_WMMA=1` alone 1,852 → 2,520 tok/s @32K (+36%), campaign total 1,586 → 2,676 (+69%) (I#1386 afterthought325).
- **WMMA dense GEMM** (fp16/bf16, P#260): 4K 778 → 1,178 (+51%), 32K 778 → 1,527 (+96%) vs `hipblasGemmEx` fallback; vs a *calibrated* hipBLASLt table WMMA still led by ~10% at 4K (P#313). Landed opt-in `STRATA_WMMA_GEMM=1` in 0.1.40.
- **Fused int8 WMMA MoE prefill kernels** (rocWMMA port of sm_80 kernels): at parity with MMQ (−0.8%) because "the pinned ggml's MMQ tiles are already RDNA3-aware (`mmq-config-rdna3.cuh`)" (P#999, REJECT recorded). Maintainer's own native gfx11 fused kernels (`native_w11_kernel`) had **a missing `__syncthreads()` after a double-buffered LDS `put()`** (45–47% intermittent failure) and **`amdgpu_waves_per_eu(8)` miscompiling on clang 22 / ROCm 7.10** (100% wrong) (I#1180); on clang 23/gfx1151 the same VGPR cap is correct and 2–15% faster per layer (P#2018) ⇒ occupancy attributes are toolchain-fragile. With fix, 7900 XT prefill 1,628 → 1,849 @32K (+13.6%).
- **Chunk-parallel GDN (WY form)** on gfx1100: fp32 folds **144× slower**, rocWMMA folds ~6× slower per layer-chunk, e2e prefill **−39/−40%** vs the serial `cols_pipe` recurrence ("rocWMMA 16×16×16 at 64×64/64×32 shapes with 4-warp blocks does not amortize fragment traffic at S=128/HV=48") (P#888, rejected).
- **Prefill method on one 7900 XTX: 925 → 2,503 tok/s** (+171%): fused int8 WMMA gate/up+down 925 → 1,092 (removed 16-expert host grouping = 37.3% of stage sum); `--resident-experts` with page-locked complement 1,092 → 2,503 (`wait copy` 52.2% → 0.1%); `--prefill auto:32768` +23% @74K; resident-set coverage below N/N silently costs 16–26% (I#1389). MoE-specific.
- **`STRATA_PF_GEMM`** (gfx11-only): +6.8–8.0% prefill on 2× 7900 XTX (I#1386), +2.6% on 7900 XT (weak-positive); left opt-in.
- **Bit-exact decode micro-opts on gfx1100** (P#2231, open, android-imdad, 7900 XTX + 9800X3D, ROCm 10.2): chat decode **+11.7%**, agent decode +14.3%, prompt +1.6–4.5%, teacher-forced KL 0.0000. Items: DPP lane exchanges in router and GDN output norm (norm **9.3 → 2.0 µs/layer**), wider HC "up" kernel (512 threads for 1–6 tokens), QSA top-k keys in registers + block scans, MTP drafter row select over 40 blocks (**12 → 2.2 µs**), multi-block argmax on HIP (**12.0 → 6.0 µs**), `hipStreamWriteValue32` landed flag (**6.7 µs** vs 15 µs host function), 256-thread PCIe plan read, two DMA streams for swaps, warp-parallel Q6_K/IQ4_XS dequant.
- **HIP router kernel** (maintainer, a2be1670): removing a serial FP64 512-add sum, 20 block barriers and global re-reads: **39 → 9–12 µs per call; router was 16% of RDNA4 decode GPU time**; bit-identical via a proof that tree vs serial sum map to the same float except in a bracketed fallback (docs/AMD_HIP.md:331-336). Gain e2e: +12% on maintainer's R9700, +1–4% inside 12–20% spread for a user (I#432).
- **PCIe auto share on gfx1100** (P#2224): in-run refinement `f = L/(L + 1.85 r)` → pcie_frac 0.25; no-regression gate only. MoE-specific.
- ROCm version matters: R9700 prompt +15–23% from 7.10 → 7.14 wheels (I#432); 7900 XTX warm decode +10% ROCm 7.1.1 → 10.2 nightly (P#745); 7900 XTX ~0.76 tok/s with every stage uniformly ~70× slow on Ubuntu 26.04/kernel 7.0 + TheRock 7.10 wheel while llama.cpp on the same toolchain was normal (I#590, open, unexplained).
- **Linux host-memory reclaim stalls**: `HSA_USERPTR_FOR_PAGED_MEM=0` ended 9 deaths/day on a 7900 XTX (Pop!_OS default `vm.swappiness=180` zram) (I#1705); on another box `GPU_PINNED_MIN_XFER_SIZE=1048576` did instead; KFD queue eviction/restore took 86 s under kswapd.
- **Desktop VRAM headroom**: 624 MiB free ⇒ amdgpu evicted ~24.5 GB to GTT in ~1 s when a desktop app allocated, OOM-killed KWin; fix `--vram-reserve-mib 3072` (I#560). Explicit cache size leaving <256 MiB free at READY collapses decode 40.9 → 16.6 (CUDA/WDDM, I#781; maintainer added a warning in 0.1.40.2).

### 4.2 Streams / queues / host sync on HIP (most transferable class)
- **Shared-expert stream fork** (fork/join per layer inside the verify graph): on HIP, "the cross-stream event dependency costs more than the shared expert takes to run" (P#826): RX 6800/Windows −12–22% (I#816), R9700 **43.4 → 63.0 tok/s (+45%) with fork off**, 2× R9700 split −22%, 2× 7900 XTX layer split 50.2 → 56.6 tok/s (+12.7%) with fork off on the same 0.1.40 build (I#1386) — but 2× RX 6900 XT Linux ROCm 10.0 **+5–13% with fork on** (I#1272). Default off on HIP (except gfx1151); per-PC calibration now measures it, keeps it only if >3% better (P#1992).
- **Mere stream creation changes speed**: an unused MTP branch stream + 2 events cost R9700 prompts 1,161 → 842 tok/s on the 2nd request (P#1240); removing it cost RX 6800/Windows prompts **16–20%** (7.9K: 805–826 vs 579–606 tok/s), bisected (I#2055, P#2056). Maintainer's R9700 experiment: extra spare streams at that spot: one 0%, two +0.7/+3.7%, three −11/−6.5% — "the number of streams created before the prompt path probably decides which hardware queue its copy and compute streams share… the real cure is to pick that stream layout on purpose".
- **Host callbacks**: CUDA host-callback thread inherited the decode thread's 1-CPU affinity ⇒ ~1000 µs per callback instead of 4 µs (I#1964); fix = start callback thread before pinning, and replace per-layer `cudaLaunchHostFunc` with a tiny stream-ordered copy into pinned memory. HIP: `hipStreamWriteValue32` 6.7 µs vs host function 15 µs (P#2231).
- **Busy-wait vs blocking sync**: Stager threads yield-spinning + non-`BlockingSync` events inherited a 1-core pin ⇒ prompt ~10× slower on GB10 (P#1101/P#1057); on Linux desktops sleep-wait is now default; Windows keeps spinning (sleep was 1.2–6% slower).
- **Commit graph without host sync**: removing a `cudaStreamSynchronize` at the end of each verify commit (~0.45 ms/round) and letting it overlap the MTP draft: +5.6% decode RTX 5090, +1.3/+2.1% 4080S (P#284); required an audit replacing implicit device syncs with explicit event waits.
- **Per-wait/record idle**: each cross-stream wait+record left ~10 µs GPU idle on WDDM; batching 16 expert gathers into one launch/one wait/one event cut kernels 51,650 → 29,550 (−43%) and prefill −6% GPU timeline on R9700 Linux (P#372).
- **Dead launches**: PCIe-call kernels launched `cap_groups` block rows that only read `n_groups` and returned (~17k blocks/window) → 4 block rows with group stride + fused SwiGLU+q8_1 (P#363; bit-exact; gain on CUDA, launch reduction reproduced but no decode gain on R9700).
- **Persistent kernel with grid barriers** for a 3-launch, 2-dependency small op (HC read, 1–8 tokens): 55.1 → 38.9 µs at 2 tokens (1.35–2.10×), −2.8/−4.2% per verify window on gfx1030; safety: every token count run once at startup with a 50 ms barrier timeout and compared to default; no occupancy API (it lied on HIP 7.1) (P#2226, open).
- **Graph branches** (parallel side branches for input-only work, PDL on sm_90+): +3% (P#904) / +1.3–4.2% (P#1889) on CUDA; `STRATA_DF_BRANCH` caused stalls with NVML queries on Linux GSP ⇒ opt-in. PDL is CUDA-only (`pdl_supported()` false on HIP).

### 4.3 Other AMD cards (mechanisms worth knowing)
- RDNA2 rocBLAS: FP16-in/FP32-out GEMMs fall back to ~5.3–5.6 TFLOPS vs 37.7 for FP16-out ⇒ FP16 in/out path doubles prompt (439 → 744–926 tok/s) (P#835); rocBLAS heuristic picks a 5.2-TFLOPS kernel for N=10240,K=2560 below T=1152 while the library's best is 6× faster ⇒ per-shape solution table (P#981; deferred, needs 10 pairs). Method advice: "`rocprofv3 --kernel-trace` on a short prompt and look at GPU time per GEMM shape, not per kernel name" (I#1386).
- `STRATA_MMQ_KQUANTS=ON` for K-quant experts on RDNA2: 633 → 1,036 tok/s; "llama.cpp RDNA2 MMQ patches that are worth +5-11% on the dense 27B (wider tiles, mad24 scales, Q8_K-style activations)" moved Strata's expert GEMM only −2/+5% (P#1897).
- gfx1151 profile (I#1258): FP16 prompt projections 17.6%, fused experts 23.5%, WMMA attention 9.7%; HC norm/upmix near memory roofline after recount. `prompt_attn_wmma_kernel` thread trace: 56% of time in `s_waitcnt vmcnt`, 0.4% in WMMA ⇒ issue a chunk's global reads before compute: −9.7% per chunk; a deeper prefetch raised VGPRs 232 → 248 and gave it all back (P#2017, author self-corrected).
- **F16 WMMA beats int8 for routed experts on gfx11** (P#2020, from "gufo"'s `RoutedF16GEMMKernel`): codes packed in LDS, each wave dequantizes its rows to F16, F16 WMMA accumulates all of K in FP32: one layer Q4_K/Q5_1 **85.3 → 53.5 ms (−37%)**, IQ3_S gate/up −15%, IQ4_NL down −23%; e2e UD-Q4_K_XL +15.6% @32K. First-token KL 0.0068 vs 0.0031 for int8 fused (opt-in).
- QSA top-k radix digit by cooperative scan: gfx1151 −5% to −49% kernel time (P#2016).

## 5. MTP / speculative findings

- **Draft-vocab coverage dominates acceptance**: bundled subset had 27 of 55,328 CJK tokens ⇒ Chinese decode +14% with no subset (I#137); fixed to 106,299 ids: Chinese +15–38%, English −1–2% (bigger head) (0.1.27). French: `en` subset misses 23.8% of French token occurrences; corpus-coverage subset (0.99) acceptance 0.505 → 0.597, decode 141 → 158 tok/s on 5090 (I#597; `tools/draft_vocab.py --corpus --coverage`).
- **`--spec-min-p` draft floor**: +10% at 0.70 on 7900 XTX, token-identity verified (P#744); R9700 sweep 0.5: 78.3, 0.7: 81.6, 0.8: 80.3, 0.9: 80.0, 0.95: 76.1 tok/s (I#432); calibrate picks 0.70 on several boxes (I#1831, I#713). `--spec 3` vs `--spec 2`: +9.5% median on 7900 XTX, 5/5 pairs (I#505); `--spec` 3/4/5/6 flat on R9700 (I#432).
- **Draft-gate bias**: under `STRATA_SPEC_PROB` the min-p gate on the *drawn* draft token's q skews sampling toward the draft's favourite (P(A)=p(A)(2−q(A)), +4.1 points, z 3.0); gating on context-only `top` is exact (I#2028).
- **Gumbel-max coupled drafts** (noise keyed by (seed, counter, token id), so draft and target agree on shared tokens): acceptance +7–10.6 points at T=1.0 (+5.7% on 2× 7900 GRE, 12/12 seeds); maintainer's 3060: 62.1% → 68.0% but decode inside spread ⇒ opt-in (P#1281).
- **MTP hidden-norm input** `--mtp-hnorm stream` vs `pooled`: acceptance 82 → 86%, decode +2.3–4% at 6K/70K, neutral 120K (I#2227, RTX 4090D).
- **Cost-aware draft policy**: `DraftPolicy::choose` picks suffix (prompt-lookup) vs MTP window from an EMA of measured round times — which makes greedy output timing-dependent when windows change CPU rounding (I#1928).
- Batch slots without MTP lose throughput (97 → 64 tok/s, I#857) ⇒ `--batch-mtp`. DFlash drafter "lower acceptance rate than MTP" (I#1161). Long context: draft acceptance fell 0.80 → 0.06 at 512K YaRN positions (P#888 aside).
- Route-tail skip (MoE) lowered draft acceptance ~1–2% decode on a 99.9%-resident V100 (I#1884).
